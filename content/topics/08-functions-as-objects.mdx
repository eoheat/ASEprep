## Intuition

In Python, **everything is an object** — ints, strings, lists, and *functions
too*. A function is a first-class object: it has a type, you can bind it to a
name, pass it as an argument, store it in a list, and return it from another
function. `is_even` is just a name pointing at a function object, exactly the
way `x` might point at the int `3`.

The other half of this lecture is **scope**: every function call creates its own
private environment (a "frame") where its parameters and local variables live.
That frame appears when the call starts, and disappears when the call returns.
Understanding scope is what lets you predict which `x` a given line is talking
about.

## The mechanics

A function always returns something. If you never write `return`, Python
silently returns `None` (a value of type `NoneType` — not a string, not zero):

```python
def is_even(i):
    i % 2 == 0        # computed and discarded; no return
# calling is_even(4) evaluates to None
```

Because functions are objects, you can alias one and use the alias to call it:

```python
def is_even(i):
    return i % 2 == 0

my_func = is_even     # NOT a call — just a second name for the same object
print(my_func(4))     # True
```

**Higher-order functions** take a function as an argument or return one. Passing
a function means passing the object, not calling it — note there are no
parentheses on `op`:

```python
def calc(op, x, y):
    return op(x, y)   # op is a function; call it here

def add(a, b):
    return a + b

print(calc(add, 2, 3))   # passes the add object -> 5
```

<Callout type="tip">
`add` (no parentheses) is the function object. `add(2, 3)` (with parentheses)
is a call that evaluates to `5`. Passing `add` to `calc` hands over the box;
`calc` decides when to open it.
</Callout>

## Worked example

Trace scope carefully. Each call gets a fresh frame; assignments inside a
function are local and do not leak out.

```python
def f(x):
    x = x + 1
    print('in f(x): x =', x)
    return x

x = 3
z = f(x)
print(x)
print(z)
```

Line by line:

- Global `x` is bound to `3`.
- `f(x)` creates a new `f` frame; its parameter `x` is bound to the *value* `3`.
- Inside `f`, `x = x + 1` rebinds the *local* `x` to `4`. This local `x` is a
  different name from the global `x`.
- `print` shows `in f(x): x = 4`; the function returns `4`.
- The call `f(x)` is replaced by `4`, so `z` becomes `4`.
- Global `x` was never touched — it's still `3`.

Output:

```python
in f(x): x = 4
3
4
```

A function can read a variable from the enclosing scope, but a plain assignment
inside the function creates a new local instead of modifying the outer one:

```python
def g(y):
    print(x)          # reads global x -> 5
x = 5
g(x)                  # prints 5
```

## Traps

<Callout type="trap">
**`None` is not nothing.** A function without a `return` returns the object
`None`. If a caller tries to use that as if it were a number or string, you get
a `TypeError` (e.g. `None + 1`), often far from where the real mistake was.
</Callout>

**`print` inside a function is not the same as returning.** `print` shows a
value on the console and the expression `print(...)` itself evaluates to `None`.
So `print(mult(4, 5))` where `mult` only *prints* its product will show the
product on one line and then `None` on the next.

**Passing `f()` when you meant to pass `f`.** `calc(add(2, 3), ...)` calls `add`
first and passes the number `5`. `calc(add, 2, 3)` passes the function itself.
The parentheses change everything.

**Assuming you can modify an outer variable by assigning to it.** Inside a
function, `x = x + 1` makes a *local* `x`; the outer `x` is unchanged. (You *can*
force global modification with the `global` keyword, but it's discouraged.)

**Reading a local before it's assigned.** `def h(y): x += 1` with `x` only
defined globally raises `UnboundLocalError` — the assignment marks `x` as local,
so the read on the right side has no local value yet.

## Memorize vs understand

| Just know it cold | Be able to derive |
|---|---|
| Every function returns something; no `return` means `None` | Whether a snippet passes a function object or a function call |
| `None` has type `NoneType`; it is not `0`, `''`, or `False`'s twin | Which `x` a line refers to given nested scopes |
| Functions are first-class objects: name, pass, return them | The output of a higher-order call by tracing frames |
| Each call creates a new frame that vanishes on return | Whether an assignment creates a local or touches an outer variable |
| Inside a function you can *read* an outer variable but not *rebind* it | Why `print(f())` shows a value then `None` |

## ASE check

```python
def mult(x, y):
    print(x * y)
print(mult(3, 4))
```

<ASECheck q="What are the two printed lines?">

`12` then `None`. `mult` prints `12` and returns `None` (no `return`). Then the
outer `print` prints that returned `None`.

</ASECheck>

```python
def f(x):
    x = x + 1
    return x
x = 10
f(x)
print(x)
```

<ASECheck q="What does the final print show?">

`10`. `f` rebinds only its *local* `x` to 11; the returned value is discarded
(not assigned to anything). The global `x` is untouched.

</ASECheck>

```python
def calc(op, x, y):
    return op(x, y)
def sub(a, b):
    return a - b
print(calc(sub, 10, 4))
```

<ASECheck q="What is printed, and why is there no error?">

`6`. `sub` is passed as an object (no parentheses), so `op` becomes `sub`
inside `calc`, and `op(10, 4)` computes `10 - 4`.

</ASECheck>

```python
def apply_twice(fn, n):
    return fn(fn(n))
print(apply_twice(lambda k: k + 3, 1))
```

<ASECheck q="What does this print?">

`7`. Inner `fn(1)` is `1 + 3 = 4`; outer `fn(4)` is `4 + 3 = 7`. The lambda is
just a function object passed as an argument. (Lambdas are covered next topic.)

</ASECheck>

<ASECheck q="A helper you wrote returns None unexpectedly and the caller crashes with a TypeError. What did you probably forget?">

A `return` statement. Without it the function returns `None`, and the caller
then tries to do arithmetic or indexing on `None`, which raises a `TypeError`.

</ASECheck>
